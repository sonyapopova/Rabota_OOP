Учебный консольный проект на C# (.NET 10), демонстрирующий основы ООП: классы, инкапсуляцию, композицию, деконструкцию объектов и работу с коллекциями.

## Структура проекта

| Файл | Назначение |
|---|---|
| `Program.cs` | точка входа, демонстрационный сценарий работы с профилем |
| `User.cs` | класс `User` — пользователь (ФИО, логин, пароль, уникальный ID) |
| `Contact.cs` | класс `Contact` — контакт пользователя (значение + ID канала) |
| `Channel.cs` | класс `Channel` — канал связи (телефон, email, telegram) |
| `UserProfile.cs` | класс `UserProfile` — профиль пользователя: контакты, денежный и бонусный балансы, персональная скидка, история покупок |
| `ProfileAdd.cs` | сервис `ProfileAdd` — создание профиля, контакты, вывод сводки, пополнение баланса и оплата покупок |
| `ProductItem.cs` | класс `ProductItem` — товарная позиция (название, цена, количество, дата покупки, итоговая стоимость) |
| `Cart.cs` | класс `Cart` — корзина товарных позиций: добавление, удаление, количество позиций, сумма |

## Что демонстрирует программа

1. Создание списка каналов связи.
2. Создание пользователя и его профиля.
3. Добавление контактов (телефон, email, Telegram).
4. Вывод сводки по профилю.
5. Удаление контакта по его ID и повторный вывод сводки.

## Бонусная и платёжная подсистема

В `UserProfile` добавлены:

- `MoneyBalance` — денежный баланс (не может быть отрицательным);
- `BonusBalance` — бонусный баланс (не может быть отрицательным);
- `PersonalDiscount` — множитель цены после скидки (от `0.01` до `1.00`);
- `BonusPaymentLimit` — максимальная доля цены, оплачиваемая бонусами (от `0.0` до `0.5`);
- `Purchases` — история совершённых покупок.

В `ProfileAdd` добавлены:

- `TopUpBalance(profile, amount)` — пополнение денежного баланса с начислением 10% бонусами;
- `PayForPurchase(profile, product, out message)` — оплата одной товарной позиции;
- `PayForPurchase(profile, cart, out message)` — оплата всей корзины с учётом персональной скидки и частичной оплаты бонусами.

Все значения проверяются: некорректные суммы, скидки и лимиты вызывают `ArgumentOutOfRangeException` / `ArgumentException`.

## Валидация и инкапсуляция

- `User`, `Contact`, `Channel` проверяют входные данные в конструкторах (`ArgumentException`, `ArgumentOutOfRangeException`).
- Свойства `User`, `Contact`, `Channel` доступны только для чтения — изменить объект после создания нельзя.
- Пароль не хранится в открытом виде: сохраняется соль и хеш PBKDF2-SHA256 (100 000 итераций), проверка — `User.VerifyPassword(...)`.
- Коллекции профиля (`Contacts`, `Purchases`) доступны только для чтения (`IReadOnlyList`), изменение — через `AddContact`, `RemoveContact`, `AddPurchase`.
- `UserProfile` имеет собственный деконструктор: ФИО, логин, количество контактов, денежный и бонусный балансы. Именно он используется при выводе сводки.

## Корзина и оплата

Единый модуль покупок, построенный на классах профиля:

- `ProductItem` — товарная позиция (название, цена, количество, итоговая стоимость);
- `Cart` — набор позиций; скидка и лимит оплаты бонусами берутся из `UserProfile`;
- `ProfileAdd.PayForPurchase(profile, cart, out message)` — считает сумму корзины, применяет `PersonalDiscount`, списывает бонусы не более `BonusPaymentLimit` от цены и не более остатка бонусов, остаток — с `MoneyBalance`;
- `ProfileAdd.CalculateMoneyPayment(profile, cart)` — сколько денег нужно доплатить за корзину при текущем балансе;
- оплаченные позиции попадают в `UserProfile.Purchases`, а корзина очищается (0 товаров, итоговая цена 0 котокоинов).

Если денег на балансе не хватает, оплата не проводится: возвращается `false`, в сообщении указывается требуемая сумма, остаток на балансе и размер недостачи, корзина и балансы остаются без изменений. После пополнения на недостающую сумму оплату можно повторить — сценарии успеха и неуспеха демонстрируются в `Main`.

Одиночная покупка поддерживается перегрузкой `PayForPurchase(profile, product, out message)`, которая просто кладёт позицию в корзину и оплачивает её.
